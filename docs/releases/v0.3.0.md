# Proof Hunters CLI v0.3.0

Mines on the Proof Hunters mining system upgraded on 28 Sep 2026 (Robinhood Chain
mainnet, chain 4663). **v0.2.3 cannot mine on the upgraded system; upgrade to v0.3.0.**
v0.1.0 remains legacy.

## Before you mine: stake to your CLI wallet

A wallet must be staked to mine. Stake **1M HUNTER tokens** to your CLI wallet's
address in the app at [app.proofhunter.fun/app/mine](https://app.proofhunter.fun/app/mine).
Print the address with `bproof wallet address --keystore <file>`. The CLI never stakes,
approves or moves tokens for you. If the wallet is not staked, the CLI sends nothing,
exits with code 4 and says:

```text
Not staked: Stake 1M HUNTER tokens to this wallet in the app: app.proofhunter.fun/app/mine (your CLI wallet address: 0x…).
```

## What changed

- **Mining on the upgraded system.** Proofs go through the mining router, sent by the
  mining wallet itself, and the Hunter NFT lands in the mining wallet in the same
  transaction. The CLI verifies the receipt, including the NFT transfer to the wallet.
- **Stake check first.** The stake is checked before the keystore is unlocked or
  anything is sent.
- **No gas on proofs that would be refused.** A proof is submitted only when the chain
  says it would be accepted for this wallet right now; otherwise the CLI keeps mining
  and sends nothing. Another miner can still win first, and a reverted transaction can
  still cost gas.
- **Expired rounds** are refreshed only once the network allows the next round.
- **Pause notice.** If mining is paused on chain, the CLI prints the notice and when it
  ends. A one-shot run exits with code 4; `--loop` waits and resumes by itself.
- **New exit code 4:** nothing was sent. JSON `status` is `notStaked`, `stakePending`,
  `waiting` or `paused`, with a plain `message`.
- **Network upkeep in `--loop`.** While the wallet is staked, the loop also sends
  occasional network upkeep transactions, as the app does: simulated first, sent after
  a random 0–30 s delay, within `--max-fee`, one at a time through the journal, and never
  while a proof is being submitted. Failures only log a neutral line. `--no-upkeep`
  turns them off; one-shot runs and the launcher never send them.
- **Loop events:** `notStaked` (the loop then stops with exit code 4), `stakePending`,
  `miningPaused`, `upkeepSent` (with `kind`), `upkeepSkipped`, `upkeepRecovered` and
  `submissionPending`. `searchStarted` and `proofAccepted` carry a `message`
  (`Mining…`, `Hunter NFT found: #N.`).
- **`--router`** pins the mining router address from the release profile. The launcher
  passes it; the CLI refuses to mine if the core reports a different router. Without
  it, the CLI reads the router from the mining core.
- **Launcher and mainnet profile** now pin the stake module and router addresses and
  their runtime bytecode hashes, alongside the core and basket.
- **Journals:** router submissions and upkeep use version 3 pending journals; versions 1 and 2 remain
  readable. Do not downgrade to an older CLI while a journal is pending.
- **Fix:** a stop that lands between two search batches no longer reports a failure.
- **Fix:** a keystore given as a bare file name (for example `--keystore wallet.json`)
  no longer fails to sync its journal directory after writing the journal.

When the mining core's module is not the upgraded one, v0.2.3 behaviour applies
unchanged. The old HUNTER boost (MiningPowerCustody) is withdraw-only and no longer
affects mining.

## Verify before running

Each release file has a GitHub build attestation and a line in `SHA256SUMS`. Follow
[release verification](https://github.com/vltgoblin/proof-hunter-miner/blob/main/docs/verifying-a-release.md).
Built with Rust 1.90.0.
